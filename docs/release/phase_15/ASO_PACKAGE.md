# Comprezza — App Store Optimization Package

**Status:** Draft for release-owner review; claims must match the exact AAB.

## Primary keywords

- photo compressor
- compress photos
- reduce photo size
- image compressor
- offline photo compressor
- compress multiple photos
- batch photo compressor

## Secondary keywords

- resize photos
- smaller image files
- save storage
- Android photo tool
- share optimized photos
- local photo processing
- compress camera photos

Avoid keyword stuffing, competitor names, unsupported “AI” claims, and “unlimited” claims.

## Search intent

| Intent | User need | Listing response |
|---|---|---|
| Reduce storage | Make photos smaller | Lead with visible file-size control and savings information. |
| Share a large photo | Create an easier-to-send output | Explain Android share-sheet workflow. |
| Privacy | Avoid cloud uploads | State local-processing design only when policy/AAB evidence supports it. |
| Batch | Compress many photos at once | Show the batch picker, bounded queue, progress, and retry in screenshots. |
| Simplicity | Avoid complex editors | Show one focused compression path. |
| Compatibility | Understand formats/devices | Describe only verified formats and device behavior. |

## Competitor analysis strategy

Do not copy competitor names or claims into metadata. Review public listings for:

- Search vocabulary.
- Screenshot ordering.
- Privacy and offline positioning.
- Review complaints about quality, storage, ads, and export failures.
- Price and monetization expectations.

Record sources, dates, markets, and observed claims. Do not claim superiority without evidence.

## Localization strategy

- Start with English listing copy and Hindi only after native-language review.
- Translate title, short description, long description, screenshots, and support copy as a coordinated set.
- Preserve product and format names where appropriate.
- Test truncation and search intent per locale.
- Do not advertise Tamil, Spanish, German, French, Arabic, Japanese, Korean, or Chinese support until translations and QA exist.

## Listing experiment rules

- Change one listing variable at a time.
- Record start/end dates, market, variant, install conversion, retention, and rating impact.
- Never test misleading screenshots or unsupported feature claims.
- Keep privacy and Data Safety statements invariant unless product behavior changes and is reviewed.

## Future ASO roadmap

1. Establish baseline impressions, conversion, retention, and ratings after launch.
2. Improve screenshot order using verified user behavior.
3. Add reviewed localized listings.
4. Test concise benefit-led descriptions.
5. Reassess category/tags after real search data.
6. Review every update against Play metadata policy.
